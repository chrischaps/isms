# Synthetic players (S1.16)

A cohort of players that play a `lab` society of Isms through the public API the way strategic people would, and write down where the game refused or confused them (ADR-0009, ADR-0010). Two kinds of brain drive them through the same tools: **scripted** strategies (free, deterministic, run in CI) and **LLM** personas on the Anthropic SDK (read the game's words, try what nobody scripted, report what they did not understand).

Nothing here reaches past the public API: no engine hooks, no database. The one exception is bootstrap, which mints each synthetic account's browser session with `isms-server session`, joins the society and creates the player's API key, exactly as a person would through the site.

## Running

```
make e2e-agents                                  # scripted cohort, two fast days in Freeport and then in the Commune, the CI gate; costs nothing
make agents PRESET=commune BRAIN=scripted        # the Commune personas: proposing, voting, standing, drawing, reading the Ledger
make agents                                      # mixed cohort, 8 players, 7 days at 10 s an hour (~30 min); needs ANTHROPIC_API_KEY
make agents BRAIN=llm PLAYERS=4 EPOCH_CYCLES=3   # every player on a model
make agents BRAIN=mixed TICK_SECONDS=5 RUN=friday
```

`make agents` seeds a fresh lab society (`PRESET=freeport` by default; `PRESET=commune` for the Commune, S2.10) in its own database, serves it on a side port (`AGENTS_PORT`, default 18090), runs the cohort to the epoch's end or the budget's, writes `docs/playtest/runs/<RUN>.md`, and replays the log with `isms-server rebuild` as the conservation check. The run's own files are under `agents/runs/<RUN>/` (git-ignored): `accounts.json` (handles and keys, so a run can resume), one `<player>.journal.jsonl` per player, `<player>.notes.md` for LLM players, `stats.json`, `summary.json`, `report.md`.

Against a server you are already running: set `ISMS_URL`, `ISMS_SOCIETY` (a lab society's id), `DATABASE_URL` (for `isms-server session`) and run `pnpm play --run <name> [--preset freeport|commune] [--players N] [--brain scripted|llm|mixed] [--model id] [--cycle-model id] [--max-usd n]`. `--preset` picks the persona list (`run.personas_for` in `config.toml`); what the society actually is (money, labor, governance, offices, the Store) is read once from `/societies/{id}/capabilities` and handed to every brain as its `SocietyFacts`, so the scripted strategies, the fuzzer's probe list and the LLM rules follow the constitution, not the flag.

`pnpm report <run>` folds a run into the report again.

## Configuration

`config.toml` holds the models, the per-turn action cap, the concurrency, the budget and the persona list; CLI flags override it; a persona's frontmatter may override the models for itself. Models are chosen from a small table in `src/config.ts` that carries each one's price and thinking parameters (`claude-haiku-4-5`, `claude-sonnet-5`, `claude-opus-5`). The budget is enforced per run in tokens and dollars; a run that reaches it stops cleanly and still writes its report.

`models.cycle_provider` chooses where the once-a-day reflection runs: `api` (the SDK, on API credit) or `claude_code`, which hands that one call to the Claude Code CLI in headless mode (`claude -p --output-format json --json-schema ...`, no tools, no session) so it runs on the account's Claude subscription. The CLI must be installed and signed in; its tokens are counted in the budget under `<model> via claude-code` at no dollar cost. The hourly turns always use the SDK, which is where the tool runner is. `--cycle-provider` overrides it per run.

## The Jev brain (SJ.1)

A third brain, `--brain jev` / `make agents BRAIN=jev`, plays the `[jev].personas` on TypeSafe's Jev, a decision model that writes no text, through OpenRouter's Decisions API (`OPENROUTER_API_KEY`); every other persona in the cast is scripted, as the contrast. Each hour, code reads the game and lays out the choices as *slots* (`src/brain/jev/candidates.ts`), each offered only when there is a reason to choose: `work` (the full menu of hours and effort while nothing is set; afterwards only a change with a reason, fatigue debt, Food falling, a thin or a fat balance), `housing` (rent the cheapest dwelling to let while unhoused), `job` (take one, or switch when an offer pays more), one slot for the persona's own business (`venture` for the founder and, after a loan, the borrower — found, fund the firm from your own pocket, hire at the median or 15% over it, sell, pay a dividend; `credit` for the borrower; `market` for the speculator; `property` for the landlord), and `plan` (move a floor of the standing plan when Food or the balance gives a reason). SJ.3 puts the missing sides of the market in: `work` offers a manager its own workplace (`work_own`: the founder hires itself at a token wage, Q160, and its hours go to its own mine or Builder, with a day's output at its rate and the wage it gives up in the sentence; `work_job` the way back, each once a day); the firm question says what the hired hands cost against yesterday's output and offers `lay_off` once a full day's record shows wages outrunning it, and `buy_<input>` for what the recipe consumes; the **lender** has a `lend` slot (a quarter of the balance at 1% or 3% a day over five days, once a day while none of its offers is open, the roll's defaults in the question); the **builder** takes the founder's road to a Builder and, for each finished dwelling, a `dwelling` slot (`sell_dwelling` at cost plus a fifth, `lease_dwelling` at the going rent, with the days of rent that equal the sale price). `[jev].floors = { market = 0.5 }` gives one slot its own confidence floor. Each option carries its tool call with the quantities and prices already worked out by the same arithmetic the scripted strategies use, and each slot ends in a do-nothing option. One `POST` sends a small state (`state.ts`: needs, balance, hours, the society's numbers, the citizen's `standing` on the scoreboard with rank, trend and the gaps precomputed, the slots' facts; no ids, no prose) and one `choice` question per slot with the persona, its `ambition` line from the frontmatter and the hour's standing sentence in the instructions (`questions.ts`); Jev answers every question in one pass with a probability on each. Code runs what was chosen, hours first, under the usual action cap; a choice under `jev.min_confidence` (or an irreversible one under `jev.irreversible_confidence`) is read as "do nothing". The journal line carries a `decisions` list and the report gains a "Jev decisions" table (held turns, mean confidence, choices the floors overruled, flip-flops, cost and latency a turn). Jev cannot say what it did not understand, so `did_not_understand` only ever names an answer to a slot or option that was never offered; the comprehension data stays the LLM brain's (ADR-0010, ADR-0014). Freeport only for now: the Commune's slots (ballots, offices, the Plan) are a follow-up.

## Personas

`personas/*.md`: frontmatter (`name`, `slug`, `brain`, `goals`, `temperament`, `risk`, optional `model`, optional `max_actions_per_turn`) and a body the LLM brain reads as "who you are". They state goals, never a script. The scripted brain's strategies live in `src/brain/scripted/strategies.ts`, keyed by slug, with a householder-like floor for slugs without one; the rule-prober is the fuzzer in `src/brain/scripted/fuzz.ts`.

Freeport's eight (S1.16): founder, wage-maximiser, speculator, saver, slacker, borrower, landlord, rule-prober; and two more from SJ.3, the other side of two markets: the **lender** (a fixed loan on the board whenever the balance covers it twice and none is open) and the **builder** (the founder's road to a Builder; each finished dwelling sold at cost plus a margin or let at the going rent, in turn). A named cast picks a list over the preset's: `--cast freeport-town` (`CAST=freeport-town PLAYERS=16` for `run.sh`) is the sixteen-player town — two founders, two lenders, a builder, a landlord, two speculators, two wage-maximisers, two savers, two slackers, a borrower, the rule-prober — among the floor's other twenty-four householders. The Commune's four (S2.10, Q149): the **steward** (stands for coordinator, publishes a Plan, opens a workplace when the Store can pay, backs what builds), the **rationer** (reads the Store; an hour onto the norm after a short day; votes by the hours), the **free-rider** (two hours at low effort, a full pantry, an hour off the norm every day), the **chronicler** (reads everything, puts the tally on every floor once, honors the top of the Ledger, votes with the room). In the Commune the rule-prober's list gains the governance probes: a ballot on a proposal that does not exist, a second ballot (checked on the roll, never counted twice), an approval ballot naming a householder, a recall of one, a Directorate field in a policy patch, a motion for an election, the rationing rule or a Plan or a workplace without holding office, standing twice, a resolution with no text, a floor that does not exist, a position at no workplace, hours past the budget under the norm. Each probe says where it applies, so the Freeport list is unchanged.

## Journals and the report

One JSONL line per turn: the clock, a small extract of the situation, the intent, every tool call with its result, every refusal verbatim (`code`, `detail`), what the player did not understand, how the turn ended, and the tokens it cost. Reflections (LLM players, once a day) and skipped hours share the file.

The cohort snapshots `/stats` and the day's `/chronicle` headlines into `days.jsonl` at each day's end (the epoch's last day from the closing read), and the scoreboard into `scoreboard.json` at the end. The report groups refusals by code and then by text with ids blanked, draws the economy day by day with each day's headlines under the table and the standings at the end, gives one paragraph to the governance tools (what was moved, cast, stood for, published, opened; accepted and refused, by whom), lists the fuzzer's findings (`DEFECT:` an accepted probe or a server error; `COPY:` a refusal that names things by raw id), groups confusions by the part of the game they name, draws one paragraph per player from the journal, and notes the turns the harness itself got wrong. Findings go to `docs/playtest/phase1-defects.md`; a known defect's probe name goes in `known-defects.txt` so `make e2e-agents` stays green until it is fixed.

## Tests

`pnpm check` (typecheck, oxlint, vitest) needs no server and no key. The tool layer is tested against recorded responses in `test/fixtures/api/` (Freeport) and `test/fixtures/commune/` (a lab Commune: the assembly with two motions and a candidacy, the Store, the Ledger, the Plan, and under `refusals/` the exact refusal each governance probe meets); `test/replay.test.ts` replays one player's recorded epoch from `test/fixtures/transcripts/` and asserts the journal matches line for line. To re-record after an API change: `AGENTS_CMD=record AGENTS_ARGS="--record rule-prober-1" PLAYERS=8 EPOCH_CYCLES=1 TICK_SECONDS=1 BRAIN=scripted RUN=rec bash scripts/agents/run.sh`, then copy `agents/runs/rec/{rule-prober-1.recording,signals,rule-prober-1.journal}.jsonl` into the fixtures. With a key in the environment and `BRAIN=llm`, the same command records a model-driven player, model exchanges included.
