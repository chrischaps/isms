# S1.15 — the epoch-end sequence: plan

Written 2026-09-18, before building. The card is TDD §18.4 S1.15 (trimmed by ADR-0009, amended by ADR-0011); the design is GDD §11.5. No model calls anywhere in this work.

## Context

The engine already ends an epoch and the operator can start the next one; everything between those two moments is missing.

What exists today:

- The tick ends the epoch at `epoch_cycles` (`phase_9_epoch_checks`, `crates/isms-core/src/tick.rs`) or on collapse, emitting `EpochEnded { reason, cycle }`; an operator can end one by hand (`Command::EndEpoch`, `Actor::System` only).
- An ended society's scheduler idles until an operator starts the next epoch (`admin_new_epoch`, S1.13d), which runs the engine's `start_epoch` for the next number: same constitution, fresh material state, the roster re-seeded.
- The Chronicle has an `EpochEnded` headline ("The epoch ends after cycle N. The ledgers close.") and per-cycle aggregates from `metrics::aggregates` (`CycleClosed.aggregates`).
- `societies` carries `epoch`, `status`, `tick_seconds`, `tick_origin`; there is no `epoch_archives` table yet (TDD §12 names its columns: society, epoch, summary jsonb, snapshot ref, closing statements).

What is missing, in the GDD's order: the announcement two days before the end, the frozen summary, the archive table and its routes, the 48-hour closing-statements window, the scheduler rolling over on its own, and a page where anyone can read a past epoch.

## What gets built, in order

1. **The announcement, two days before the end** (engine, PR).
   - At the close of cycle N−2 the tick emits `Event::EpochEnding { final_cycle }`, appended after `OfferWithdrawn` (append-only: `kind()`, `ALL_KINDS`, `apply/tests.rs` pins updated). `apply` records `world.meta.epoch_ending: Option<Cycle>` so views can show a countdown.
   - Freeport's Chronicle gets a template: "Two days remain in the epoch. Settle what you can."
   - Collapse and an operator's end give no warning, by design; the GDD row says so.
   - Q115: does a society whose `epoch_cycles` is under three announce at all? Provisional: no announcement when `epoch_cycles ≤ 2`.

2. **The final resolution and the frozen summary** (engine, same PR).
   - `EpochEnded` gains `summary: EpochSummary`: the last cycle's aggregates, population and active humans, firm count, price index, the scoreboard's top ten (citizen, net worth, self-made), and every citizen's net worth. Computed in the same tick from the scratch world, so replay reproduces it byte for byte. No new mutable state in `World`.
   - Goldens regenerated (the `EpochEnded` payload grows); the fold-equals-live property covers it.

3. **`epoch_archives`** (store and server, main).
   - Migration `0007_epoch_archives.sql`: `society_id`, `epoch`, `ended_at`, `reason`, `final_cycle`, `summary jsonb`, `ended_seq` (the `EpochEnded` event), `closes_at` (the statements window), `closing_statements jsonb` (citizen id, handle, text, written at). Primary key (society_id, epoch).
   - The actor writes the row when it commits `EpochEnded` (same transaction as the event append, so a crash cannot leave one without the other).
   - Routes: `GET /public/societies/{id}/archives` and `/archives/{epoch}` (read-only; a `lab` society stays 404 as every `/public/*` route does), and `POST /s/{id}/closing-statement` (one per citizen, editable until `closes_at`; refused `epoch_ended`-style after it, with a named code).

4. **The window and the rollover** (server, main).
   - `epoch.closing_window_hours = 48` in `presets/_base.toml` (a tunable, so it goes in the engine PR's preset change), overridable per society at seed like `tick_seconds`, so tests and lab societies use minutes.
   - The scheduler, which idles on an ended epoch today, sleeps until `closes_at` and then calls `new_epoch` itself; the operator's "Start epoch" during the window means "start now" and closes the statements early.
   - The Chronicle's `EpochStarted` headline already exists.

5. **The archive page** (web, main).
   - `/s/{id}/archives`: one card per past epoch with the summary, the closing statements in arrival order, and the citizen's own statement box while the window is open. Home shows the countdown once `epoch_ending` is set.
   - Public: the same page under `/public/societies/{id}/archives` for spectators.

6. **Harness** (main). The `epoch_end` signal already stops a run; the lab seed sets a one-minute window so `make e2e-agents` sees the rollover inside its two-day run and the report notes it.

## Tests named in the done gate

- Engine: `tick.rs::the_epoch_announces_two_cycles_before_its_end`, `tick.rs::an_epoch_ended_carries_the_frozen_summary`, `tick.rs::a_short_epoch_does_not_announce`; goldens; proptest green.
- Server: `runtime.rs::the_epoch_ends_archives_and_rolls_over_after_the_window` (a lab society with `epoch_cycles = 2` and a one-minute window; asserts the archive row, then epoch 2 ticking), `society_api.rs::a_closing_statement_is_kept_until_the_window_closes`, `api.rs::a_lab_society_has_no_public_archive`.
- Web: a Playwright step reading the archive after the operator ends an epoch; unit tests for the countdown text.
- `make e2e-agents` green with the rollover in its log.

## Sequencing

1. One engine PR: steps 1 and 2 plus the `closing_window_hours` tunable. Branch `s1.15-epoch-end`, in `../Isms-p1`, one cycle at a time.
2. On main, against the event shape from the PR: step 3 (migration, actor write, routes), then step 4 (scheduler), then step 5 (web), then step 6. Three or four commits, `make push` each.
3. Then the load test and the T5 measurement, on a build with the rollover, so an epoch's worth of events includes the archive write.

## Decisions to confirm

- The summary is the engine's, carried on `EpochEnded`, so replay reproduces it; the server does not compute it from the store.
- Closing statements are per citizen, one each, editable until the window closes, kept in the archive row rather than as events (they are not economic facts and never replay).
- The window is a preset tunable, not a hard 48 hours.
