# Open questions and provisional answers

Where the GDD and TDD are silent or contradict each other, the executing agent records the question and a provisional answer here and proceeds on it. Each answer is in force until Chris overturns it; overturning one is an edit here plus, if code changed, an ADR. Structural deviations from the TDD are ADRs in `docs/decisions/` (referenced below), not entries here.

Numbering is stable; do not renumber. Add new entries at the end.

|---|---|---|---|---|
| Q1 | TDD 9.3 legacy-manager script never buys inputs, so Mills, Foundries and Workshops would starve (production consumes from the owning org's inventory, TDD 5.5 phase 4). | Each tick the legacy manager bids for the shortfall between org inventory and one cycle's recipe demand at `last_price x (1 + legacy_markup)`. Amends TDD 9.3. | S0.12b | provisional |
| Q2 | Legacy hiring is uncapped: 40 householders at `legacy_wage` x 8 h is ~2560/cycle payroll against ~1900/cycle household spend at start prices, so treasuries drain and the machine-buy trigger never fires. | Script rule: a legacy firm posts no new job offers while inventory exceeds `legacy_hire_inventory_cycles_cap` cycles of last-cycle sales. S0.14 may still need an engine session; pre-authorised as S0.14b. | S0.12b, S0.14 | provisional |
| Q3 | T20 fatigue debt: is "high effort" per citizen or per allocation? Does hardship debt recur? When is `budget` set (TDD 6 says cycle start, 5.5 says 8h at cycle end)? | A cycle is high-effort if any allocation with hours > 0 was High at cycle end. Hardship debt recurs each hardship cycle. Step 8h at tick 23 sets next cycle's `budget`; that is the same moment as "cycle start". | S0.5, S0.6a | provisional |
| Q4 | What happens when the new budget is below the sum of existing allocations, and is the D6 constraint on the rate or the cycle total? | Allocations are a rate. `SetLabor` validates sum(hours) <= budget at submission. Phase 3 uses `min(sum(hours), budget)` scaled pro rata without mutating allocations, so no synthetic `LaborSet` is emitted. | S0.6a | provisional |
| Q5 | Hours per tick are fractional (8/24) but TDD 5.9 forbids accumulating f64 across ticks; `hours_in_family`, `cycle_output` and piece-rate attribution all accumulate. | Labor is stored as integer tick-hours (`u32`, each tick adds `hours`); real hours = tick_hours / 24. Hourly pay = `wage_cents x tick_hours / 24`, floored; the remainder stays in the treasury. f64 only in `output_remainder` and per-cycle attribution that resets at 8a. Transcendentals go through `libm` so MSVC and glibc agree. | S0.6a, S0.10a | provisional |
| Q6 | Are standing-plan internal commands persisted, with what `client_kind`, and do they count as presence? | Persisted in the tick's event vector with a new `ClientKind::Plan`. Only Web/ApiKey commands and `Seen` update `last_seen_tick`. Householders are exempt from dormancy (they emigrate instead). | S0.9 | provisional |
| Q7 | `tick()` cannot refuse to run after `EpochEnded` (S0.4 gate says tick 1008 is never produced). | `tick` returns `Result<Vec<Event>, TickError>`; `TickError::EpochEnded` when the epoch has ended and no new epoch was started. | S0.4 | provisional |
| Q8 | "Last price" before any trade, and for shares and dwellings; `TickResolved.last_prices` duplicates state that `Trade` already moves. | `last_price(instr)` = last `Trade`, else `start_prices[good]`, else book value for shares, else None. `apply(Trade)` is authoritative; `TickResolved` carries only VWAP and index statistics. | S0.8 | provisional |
| Q9 | `founding_cost_money` is debited but Freeport has no treasury (A6 = none). Where does it go? | `Burned`, with `RuleId::founding_fee`, so conservation holds. Householders never found. | S0.10a | provisional |
| Q10 | How does a human `Join` a simulated society when the actor is not yet a citizen? | `Envelope.actor = System`, `client_kind = Sim`, `Join { handle, kind: Human }`; `CitizenJoined` assigns the next id. | Q11 | Starting state of a joiner beyond "equal money and nothing else". | Meters start at `meter_start` = 100, pantry empty, unhoused. Shelter decays until a lease, so legacy Builders must let the 40 `initial_dwellings` in cycle 0. | S0.5, S0.12 | provisional |
| Q12 | GDD gives a pantry cap of 48 for Food only; S0.7 enforces "pantry caps" and citizens may buy Machines and Materials. | `pantry_cap` is per good: 48 for Food and Wares, unlimited otherwise. A bid is rejected if `pantry + open bid qty + qty > cap`. | S0.7, S0.8 | provisional |
| Q13 | Is the hardship test (Food < 20 for a full cycle) measured before or after eating? | The Food meter at the end of phase 5, at every tick 0..23 of the cycle. | S0.5 | provisional |
| Q14 | S0.2 needs numbers that exist nowhere: Republic tax defaults, Commonwealth levy, the cross-axis constraint list, the lexicon key set. | `tax_rate` 0.20 flat, `need_floor_food` 24, `capital_levy` 0.01 per cycle (all `[new tunable] S0.2`). Constraints: need => pricing=none and redistribution=total; pricing=none => compensation=need; capital=open => ownership=private; ownership=collective => capital=none; labor=assigned => governance=committee; compensation=share => ownership=cooperative; governance=none => redistribution=none and pricing != administered. Lexicon keys are listed in `presets/lexicon/KEYS.txt`. | S0.2 | provisional |
| Q15 | Householder "living cost" and legacy job-offer terms are undefined. | Living cost = 24 Food + 4 Wares at last price + current rent. Legacy offers: max 8 h, open-ended term, 1-cycle notice. | S0.12b | provisional |

S0.6 fixtures insert assignments directly; from S0.10 `AcceptEmployment` is the only producer of assignments in Freeport. | S0.6a, S0.10a | provisional |
| Q17 | Builders produce Dwelling assets, but dwellings arrive in S0.11. | The Builder arm of production is a tracked no-op in S0.6 (listed in the unimplemented registry) and is completed in S0.11a. | S0.6b | provisional |
